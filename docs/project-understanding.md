## 球桌上的元素

| 元素 | 画面特征 | 含义与作用 |
| --- | --- | --- |
| 球桌 | 白色背景的长方形区域 | 比赛使用的逻辑尺寸为 800 × 450，画面按可用区域等比例缩放 |
| 边墙 | 外围黑色线条 | 使冰球反弹；左右两侧中央留出球门开口 |
| 中线 | 球桌中央的浅色竖线 | 划分左右半场，双方球拍分别受本方半场范围限制 |
| 中央圆圈 | 球桌中央的浅色圆圈 | 标示中央发球位置，半径为 60 |
| 左方球拍 | 左半场的大圆圈 | 对应 `p1`，半径为 30 |
| 右方球拍 | 右半场的大圆圈 | 对应 `p2`，半径为 30 |
| 冰球 | 内部带十字的小圆圈 | 对应 `puck`，半径为 20，能够移动、反弹和旋转 |
| 冰球十字标记 | 冰球内部的两条交叉线 | 随 `rotation` 转动，让旋转变化可以辨认 |
| 球门 | 左右边界中央的开口 | 开口高度为 160，各自以球桌高度中央为中心 |
| 球门屏障 | 球门开口中的灰色竖线 | `leftGoalIntegrity` 与 `rightGoalIntegrity` 分别表示左右屏障是否完整 |
| 球门端点 | 开口上下两端与边墙相接的位置 | 四个端点分别进行冰球碰撞检查 |
| 球门禁区 | 球门前的浅色半圆 | 半径为 85；比赛进行时，球拍中心与球门中心至少相隔 115，使半径为 30 的球拍停留在禁区之外 |
| 比分 | 左右半场中的浅色大数字 | 分别显示左方和右方已经得到的分数 |
| 速度读数 | 球桌下方的 `v = …` | 冰球速度经过平滑处理后乘以 3，再取整数；没有标注物理单位 |

中线、中央圆圈和比分没有与冰球进行碰撞。球门禁区只约束球拍，冰球可以通过。比赛结束后的球拍移动只保留半场与外围范围限制。

来源：[components/Hockey.tsx](../components/Hockey.tsx) 中的尺寸常量、球拍范围限制、球门碰撞与绘制代码。

## 本地操作

| 操作对象 | 输入 | 具体含义 |
| --- | --- | --- |
| 左方球拍 | `W`、`A`、`S`、`D` | 分别向上、向左、向下、向右移动，可以组合按键 |
| 左方球拍 | 移动鼠标 | 鼠标位置转换为球桌坐标后，球拍跟随该位置；每次更新有移动距离限制 |
| 左方球拍 | 在游戏画布上移动手指 | 第一根触摸手指的位置作为球拍目标位置；代码监听 `touchmove` |
| 右方球拍 | 方向键 | 本地双人对战中，`ArrowUp`、`ArrowLeft`、`ArrowDown`、`ArrowRight` 分别控制四个方向 |
| 击球 | 移动球拍接触冰球 | 碰撞自动计算，无须点击鼠标或者按下额外的击球按钮 |
| 主动击球 | 迎向冰球移动球拍 | 球拍朝向冰球的运动会增加出球冲量与额外击球力度 |
| 卸力接球 | 接触来球时，顺着来球运动方向移动球拍 | 可以降低接触时的相对法向速度，从而减小碰撞冲量；冰球仍受最低速度规则影响 |
| 旋转击球 | 接触时让球拍沿接触面方向运动 | 接触面的切向相对速度改变冰球旋转，后续运动受到 Magnus 效应影响 |
| 切换模式 | 点击 `HUMAN VS AI` 或者 `HUMAN VS HUMAN` | 在人机对战与本地双人对战之间切换，并调用比赛重置 |
| 重置比赛 | 点击 `Reset Game` | 清零双方比分、清除获胜方与彩条，把冰球放回中央并赋予水平初速度 |
| 返回大厅 | 点击 `Back` | 离开本地游戏页面 |

左方存在有效的 WASD 方向输入时，优先使用键盘移动。方向输入相互抵消时，鼠标跟随仍可生效。鼠标无须按住按钮。

人机对战默认开启，右方由 AI 对手控制。本地双人对战需要两名玩家共享设备。移动操作会受半场边界和球门禁区约束。

`resetGame` 会清零比分并清除获胜方，将冰球和球拍恢复到初始位置，同时恢复屏障、旋转、进球过程、碰撞效果与彩条的初始状态。

来源：[GameLocal.tsx](../src/app/screens/GameLocal.tsx)、[Hockey.tsx](../components/Hockey.tsx) 中的输入监听、移动逻辑、碰撞逻辑和 `useImperativeHandle`。

## 比赛与得分规则

1. 比赛开始时，冰球位于中央，随机向左方或者右方发出。
2. 双方通过移动球拍接触冰球。冰球可以碰撞边墙，旋转会使其运动方向产生弯曲。
3. 球门屏障的击破条件要求冰球朝向对应球门运动，水平速度绝对值至少达到 6，并接触屏障的有效区域。接近开口端点时会触发端点保护反弹。
4. 球门屏障打开后，冰球完整越过左侧边界时右方进球，完整越过右侧边界时左方进球。
5. 进球后进入慢动作。庆祝计时结束时，进攻方增加一分。
6. 得分尚未达到七分时，冰球回到中央，双方屏障恢复完整；初始水平运动朝向本次失分方。
7. 一方达到七分时，比赛结束，显示 `PLAYER 1 WINS` 或者 `PLAYER 2 WINS`，并生成获胜方彩条。球拍仍可移动。

冰球的目标最低速度为 6、目标最高速度为 50。最高速度使用逐次衰减处理，瞬时速度可以超过该数值。速度与旋转都会随时间衰减，旋转强度限制在 -0.7 至 0.7。

进球慢动作把运动时间缩放至正常值的 0.1；庆祝计时使用 60 次主循环更新，实际持续时间随更新频率变化。

来源：[Hockey.tsx](../components/Hockey.tsx) 中的 `resetPuck`、`checkBarrier`、边界检查和 `goalActive` 处理。

## 连击爆发与 AI 对手

**连击爆发**：连续两次球拍接触的位置相距小于 100 时，连击次数递增；位置相距达到 100 时，次数重新记为一次。计数达到四次时，冰球以随机方向、速度 50 弹出，并给当前球拍施加反向后坐。该计数依据接触位置，双方球拍接触共用同一个计数。

**AI 移动**：右方判断冰球是否正在接近、是否已经进入右侧附近以及水平速度是否较小。适合进攻时，AI 接近预计拦截位置；其他时候回到防守位置并跟随冰球高度。

**AI 旋转选择**：AI 击球后，会预测不同旋转值对应的球路，考虑边墙反弹、抵达左侧球门的可能性、与左方球拍的距离及剩余速度，再选择旋转值。`ENABLE_AI_SPIN_PLANNING` 当前为 `true`，人机对战中的这一功能开启。

来源：[Hockey.tsx](../components/Hockey.tsx) 中的 `consecutiveHits`、AI 移动和 `scoreSpin`。

## 碰撞与庆祝效果

| 效果 | 触发与含义 | 当前代码状态 |
| --- | --- | --- |
| 击球停顿 | 一般球拍碰撞后短暂停止比赛运动，加强打击感 | 开启；通常根据出球速度得到 4 至 35 个逻辑帧的停顿 |
| 左方轻触 | 左方球拍速度小于 2、单次位移小于 1.5 时的接触 | 不追加通常的旋转与停顿；连击爆发另有处理 |
| 蓝色速度箭头 | 停顿期间显示当前出球速度方向，箭头长度随速度增大 | 开启；箭头越过画面边缘后从另一边继续绘制 |
| 红色旋转箭头 | 停顿期间显示旋转方向和强度 | 旋转绝对值大于 0.05 时显示，并带有一次摆动动画 |
| 碰撞变形 | 冰球沿碰撞方向压缩，随后恢复 | 与较明显的球拍碰撞一起触发 |
| 碰撞波纹 | 从接触位置扩张的圆环 | 球拍、边墙等碰撞通过 `triggerImpact` 生成 |
| 碰撞火花 | 从接触位置喷出的短线 | 带有运动与重力效果，逐渐消失 |
| 屏障碎片 | 破门时从门口向外喷出的灰色线段 | 由屏障击破事件生成 |
| 画面震动 | 球桌整体短暂移动 | 冲击越明显，震动通常越强 |
| 冲击反色 | 冰球周围逐渐扩张的反色圆形区域 | 仅在触发停顿的冲击强度大于 100 时启用，当前可触发性未经页面验证 |
| 进球慢动作 | 冰球越过已经打开的球门后放慢运动 | 得分结算前的庆祝过程 |
| 胜利彩条 | 获胜方半场边缘向内喷出彩色线段 | 生成 220 条，随阻力减速并停止 |
| 胜利文字 | 中央显示获胜的参赛方 | 与比赛结束一起显示 |

蓝色箭头跨越边缘的绘制方式用于容纳箭头长度。它显示当前速度向量，球路后续仍会受到碰撞与旋转影响。

`ENABLE_HITSTOP_CONTROL` 当前为 `false`。玩家在停顿期间通过鼠标后移调节速度与旋转的功能关闭；蓝色速度箭头、红色旋转箭头和击球停顿仍有各自的显示逻辑。[hitstopControl.ts](../hitstopControl.ts) 保留相关计算函数，目前游戏组件只从该文件导入 `initHitStopControlState`。

来源：[Hockey.tsx](../components/Hockey.tsx) 中的 `triggerImpact`、`triggerGoalEffect`、`spawnConfetti` 和效果绘制代码。

## 大厅与房间操作

| 界面文字 | 含义 | 当前处理 |
| --- | --- | --- |
| `Name` | 玩家名称 | 初始名称为 `Player` 加三位数字；最多输入 18 个字符，空白名称按 `Player` 处理 |
| `Local` | 进入本地游戏 | 无须等待大厅连接成功 |
| `Create Room` | 创建一个两人房间 | 向大厅发送 `room:create`，收到创建结果后切换到房间页面 |
| `Search / Join by Room ID` | 输入六位房间编号 | 去除两端空白并转换为大写；只有有效编号才会开放加入操作 |
| `Join` | 按编号请求加入房间 | 通过大厅 WebSocket 发送 `room:join`；加入成功后房间页面显示双方比赛 |
| `Enter` | 从列表进入指定房间 | 向同一大厅连接请求加入该房间 |
| `Rooms` | 房间列表 | 按创建时间从新到旧排列，显示编号与人数 |
| `No rooms found.` | 当前列表为空 | 搜索后没有匹配项时也显示这段文字 |
| `CONNECTED` | 大厅状态消息已经收到 | 页面已经收到 `lobby:state` |
| `CONNECTING…` | 正在建立大厅连接 | 页面开始连接时设置 |
| `Copy ID` | 复制房间编号 | 向系统剪贴板写入编号 |
| `Leave` | 离开当前房间页面 | 请求退出房间并返回大厅，继续使用当前大厅连接 |
| `HOST` / `GUEST` | 当前联机角色 | 房主控制左侧，加入者控制右侧 |
| `1/2` / `2/2` | 当前人数与房间容量 | 一个房间最多两个玩家 |
| `Waiting for opponent` / `Ready` | 房间人数状态 | 分别表示一人等待、两人均已加入 |
| `RTT` | 大厅消息往返时间 | 约每两秒发送一次 ping，收到 Worker 回应后显示本机测得的往返毫秒数 |
| `Reset Game` | 重新开始当前比赛 | 仅房主可用，会重置比分、冰球、球拍与球门屏障 |
| 错误文字 | 当前请求或者连接的错误 | 例如房间不存在、房间已满、网页来源不允许、连接失败 |

房间进入 `2/2` 后即可对战。Worker 直接使用大厅 WebSocket 双向传送比赛数据。

## 联机角色与通信

| 环节 | 职责 | 对应位置 |
| --- | --- | --- |
| 大厅服务 | 保存当前连接与临时房间、校验消息、检查网页来源、转发比赛输入和快照 | Cloudflare Worker 与名为 `global` 的 `Lobby` Durable Object |
| 大厅连接 | 交换房间操作、输入、比赛状态与延迟测量消息 | 自动连接 `/ws` WebSocket；正式网址来自项目构建配置 |
| 房主比赛职责 | 控制左方、接收访客输入、计算比赛并每秒发送约 20 次快照 | `Room` 与 `Hockey` 的 host 分支 |
| 访客比赛职责 | 使用 WASD、方向键、鼠标或者触摸控制右方；接收比赛快照并显示 | `Room` 与 `Hockey` 的 guest 分支 |

访客输入发送间隔至少为 50 毫秒。键盘状态和转换为球桌坐标的鼠标或者触摸位置都会传送给房主。

比赛快照包含 `p1`、`p2` 的位置与比分，`puck` 的位置、速度、旋转强度和角度，双方屏障完整状态、获胜方、碰撞粒子、波纹、球体压缩、画面震动与进球慢动作状态。访客直接显示房主提供的状态。

大厅将连接状态保存于 Durable Object WebSocket attachment，在休眠恢复时重新装载。房主断开或者离开会关闭房间；访客离开会腾出访客席位。Worker 限制允许的网页来源，并限制请求大小与消息速率。

来源：[src/net/protocol.ts](../src/net/protocol.ts)、[src/net/lobbyClient.ts](../src/net/lobbyClient.ts)、[cf/worker/src/protocol.ts](../cf/worker/src/protocol.ts)、[worker.ts](../cf/worker/src/worker.ts)。

## 当前联机行为的源码边界

实际在线服务当前读取正式网页地址；本地开发与测试连接本机 Worker。访客输入传送给房主，比赛由房主单独计算。

浏览器连接断开时会进行退避重连并显示大厅入口。离开房间的玩家需要重新加入仍然存在的房间；房主连接断开会关闭房间。
